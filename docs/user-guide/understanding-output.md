# Understanding Outputs

The BioRemPP workflow produces a structured results tree. This page explains what each artifact family represents and where it fits in the validation chain.

## Output Families

| Family | Location | Purpose |
|---|---|---|
| Database exports | `results/database/` | release-scoped CSV and XLSX versions of the final assembled database |
| Analysis artifacts | `results/analysis/` | machine-readable summaries used for interpretation and cross-checking |
| Metadata and integrated validation | `results/metadata/` | KEGG release tracking and rule-level validation reports |
| Workflow report | `results/reports/` | consolidated summary with release context and artifact hashes |
| GX validation outputs | `biorempp_validation/results/` | checkpoint results and validator summary for the generated release |

## Database Exports

The final database contract is:

- `results/database/biorempp_database_v1.1.0.csv`
- `results/database/biorempp_database_v1.1.0.xlsx`

The CSV uses delimiter `;` with quoted fields enabled. The exported column order and field semantics are defined in the [Schema](../database-reference/schema.md).

## Analysis Artifacts

The workflow generates nine JSON analysis artifacts:

| File | Role |
|---|---|
| `basic_statistics.json` | top-level counts and core descriptive totals |
| `compound_statistics.json` | compound-centric summaries and rankings |
| `ko_statistics.json` | KO-centric summaries and rankings |
| `enzyme_statistics.json` | enzyme activity summaries and rankings |
| `gene_statistics.json` | gene symbol and gene name summaries |
| `crosstab_statistics.json` | cross-tabulated summaries across key dimensions |
| `database_metadata.json` | release metadata and structural context for the generated database |
| `executive_summary.json` | condensed summary of the main analytical signals |
| `complete_analysis.json` | merged analysis bundle for downstream consumption |

These files are not optional side products. They are part of the `all` rule contract and are also consumed by the GX validator in `internal_consistency` and `regression_detection` mode.

## Metadata And Integrated Validation

Three files in `results/metadata/` are especially important for review:

### `kegg_release.json`

Tracks the KEGG release context used by the workflow.

### `keys_consistency_report.json`

Explains whether remaining missing values in `ec` or `reaction` are justified under the current KEGG-based validation logic.

### `links_groundtruth_policy_report.json`

Summarizes how database rows relate to the KEGG link policy, including policy-aware coverage metrics and pair-level validation details.

## Workflow Summary

`results/reports/workflow_summary.json` is the most compact release-level summary generated by the pipeline. It currently consolidates:

- pipeline identity and version
- KEGG release provenance
- justification totals from `keys_consistency_report.json`
- policy-aware link metrics from `links_groundtruth_policy_report.json`
- reaction description coverage
- SHA256 hashes and sizes for the main release artifacts

This file is the best single JSON document for audit-oriented review of a completed run.

## How To Read Missing EC Or Reaction Values

Not every `NA` in the final database indicates an error. The active validator contract explicitly allows nullable values in:

- `ec`
- `reaction`
- `reaction_description`

The correct place to interpret remaining missing values is `results/metadata/keys_consistency_report.json`, not the CSV alone.

## GX Validation Outputs

After running the standalone validator, inspect:

- `biorempp_validation/results/critical_checkpoint_result.json`
- `biorempp_validation/results/warning_checkpoint_result.json`
- `biorempp_validation/results/validation_summary.json`
- `biorempp_validation/results/data_docs/index.html`

`validation_summary.json` is the fastest way to confirm whether the release passed all configured checks.
